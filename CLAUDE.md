# Claude Code Instructions

This is a fictional practice repository for learning GitHub. The learner is not building a real production skill.

## How To Help

- Inspect the repo before editing.
- Explain the repo structure in plain language.
- Ask the learner for their first name and a fake workflow idea if either is missing.
- Create one fake skill under `skills/<first-name>-<skill-name>/SKILL.md`.
- Follow the README skill naming and structure rules.
- Help the learner review, commit, push, and open a pull request after the skill is created.

## Do Not Use Real Context

Do not pull from:

- Personal files.
- Personal history.
- Private notes.
- Company context.
- Customer data.
- Internal workflows.
- Credentials or secrets.
- Real workplace documents.

Invent fictional examples. Keep everything safe for a public GitHub repository.

## GitHub Flow

The expected flow is:

1. Fork the repo (Fork button on GitHub, or `gh repo fork` if the learner has the GitHub CLI).
2. Clone the learner's fork, not `aninhTT/practice-github-skills`.
3. Create a branch.
4. Add one fake skill.
5. Commit.
6. Push the branch to the learner's fork.
7. Open a pull request from the fork into `main` on `aninhTT/practice-github-skills`.
8. Tell the learner the PR will stay open until the repo owner is back after Q1 2027, and that they're done.
9. Optional, only if the learner asks: open a second PR inside their fork (branch into the fork's `main`) and help them merge it.

Do not recommend direct pushes to `main`.

The repo owner is on leave through the end of Q1 2027. Do not tell learners to request write access, open an access-request issue, or message the owner.
